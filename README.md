# 経済指標カレンダー (Google Apps Script)

ナスダックに効く経済指標だけを選抜して、**Google カレンダーに自動で入れる**スクリプトです。
Google のサーバーで動くので、PC を開いていなくても、サーバーを借りなくても、
毎日勝手に更新されます。

```
09/14(月) 21:30 🔴🇺🇸 米 消費者物価指数 (CPI)          予想 0.3%
09/15(火) 21:30 🟠🇺🇸 米 小売売上高
09/17(木) 03:00 🔴🇺🇸 FOMC 政策金利発表
09/17(木) 03:30 🔴🇺🇸 FOMC 議長記者会見
09/18(金) 22:30 🟡🇺🇸 クアドラプル・ウィッチング (四半期 SQ)
09/28(月) 21:30 🔴🇺🇸 米 PCE デフレータ (個人所得・支出)
```

---

## 何ができるか

| | |
|---|---|
| **ナスダック影響度で選抜** | 全 42 指標に 0-100 のスコアを付け、しきい値以上だけを登録。CPI・雇用統計・FOMC は 90 以上、住宅系は 50 前後、と重み付けしてある |
| **日本時間で表示** | 米東部時間で管理し、夏時間も含めて自動変換。予定の詳細には現地時刻も併記 |
| **重要度で色分け・通知** | 🔴 最重要 / 🟠 重要 / 🟡 注目 / ⚪ 参考。最重要だけ「前日 + 30分前」に通知、と段階を分けられる |
| **発表時刻も一次情報から** | BLS・BEA・センサス局の発表予定表を読み、時刻も機関の公表値そのものを使う。載っていない指標は「未確認の暫定値」と明記する |
| **なぜ効くかを説明文に** | 「コア前月比が予想を 0.1pt 外すだけで指数が 1-2% 動く」といった解説を各予定に入れてある |
| **予想・前回・結果を表示** | 発表後は結果値を取り込んで件名に反映（investing を有効にした場合） |
| **指標以外の重要日も** | 米国市場の休場・短縮取引・SQ・指数リバランス・主要ハイテク銘柄の決算日 |
| **週次まとめ** | 月曜に「今週の注目指標 6件（最重要 3件）」という終日予定を自動作成 |
| **FOMC 日程も自動** | 手入力が尽きた先の年は Fed の公式ページから取得。妥当性検査に落ちたら取り込まない |
| **毎日自動更新** | 時間主導型トリガーで1日2回。予定の変更・追加・削除まで面倒を見る |
| **何度実行しても安全** | 予定 ID を内容から決めているので、重複が絶対に増えない（冪等） |
| **静かに壊れない** | 同期の失敗と、日程データの期限切れをメールで知らせる |

## セットアップ（10分・1回だけ）

### 1. スクリプトを作る

1. [script.google.com](https://script.google.com/) を開いて **［新しいプロジェクト］**
2. `dist/Code.gs` の中身をまるごとコピーし、エディタの `コード.gs` を**全部置き換える**
3. 左メニューの **［サービス］の ＋** → **Calendar API** を選んで **［追加］**
   （識別子は `Calendar` のまま。これを忘れると `Calendar is not defined` になります）
4. 左下の **［プロジェクトの設定］** → タイムゾーンを **(GMT+09:00) 日本標準時** に
5. 画面上部でプロジェクト名を「経済指標カレンダー」などに変更（任意）

> `clasp` を使う場合は `.clasp.json.example` を `.clasp.json` にコピーして
> スクリプト ID を書き、`npm run push` で `src/` をそのまま反映できます。

### 2. 実行する

エディタ上部の関数プルダウンで **`setup`** を選んで **［実行］**。

初回だけ権限の確認が出ます。

- 「承認が必要です」→ **［権限を確認］**
- 「このアプリは Google で確認されていません」→ **［詳細］** →
  **［（プロジェクト名）（安全ではないページ）に移動］**
- 権限の一覧を確認して **［許可］**

自分で作ったスクリプトを自分のアカウントで動かすので、この警告は正常です。
**一度承認すれば期限切れはありません。**

実行ログにこう出れば完了です。

```
─────────────────────────────
 セットアップ完了
─────────────────────────────
カレンダー : 経済指標 (Nasdaq)
同期結果   : 新規 57 / 更新 0 / 削除 0 / 変更なし 0
自動実行   : 毎日 6時ごろ / 20時ごろ
```

Google カレンダーを開くと「経済指標 (Nasdaq)」が増えています。**以上です。**

### 3. （任意）発表日を公式の確定値にする

これをやらないと、CPI などの日付は「過去の慣例からの推定」のままで、
件名に `(予定日未確定)` が付きます。

1. [FRED の API キー](https://fred.stlouisfed.org/docs/api/api_key.html)を無料で取得
2. **［プロジェクトの設定］** → **［スクリプト プロパティ］** → プロパティを追加
   - プロパティ: `FRED_API_KEY`
   - 値: 取得したキー

Slack / Discord に週次のまとめを流したい場合は、同じ場所に
`WEBHOOK_URL` を追加してください。

## 自動で動くもの・自分でやること

| | 自動か | |
|---|---|---|
| 毎日の同期（追加・更新・削除） | ✅ 完全自動 | 1日2回、Google のサーバーで実行 |
| 発表結果の取り込み | ✅ 完全自動 | 夕方の回が過去5日ぶんを再同期 |
| 同期の失敗 | ✅ 自動でメール | Google からの失敗通知とは別に、原因つきで届く |
| 認証の期限切れ | ✅ 起きない | 自分のアカウントで動くので失効しない |
| FOMC 日程の翌年分 | ✅ 自動取得 | Fed の公式ページから補う（下記） |

### FOMC の会合日程

会合日程だけは計算では出せないので、Fed が公表したものを読むしかありません。
`src/02_meetings.js` に手入力した日程を持ちつつ、**それが尽きた先の年は
[Fed の公式ページ](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm)
から自動で取得**します。

相手は HTML なので、いつ形が変わってもおかしくありません。そこで

> **抽出はゆるく、採用は厳しく**

という方針にしてあります。取り出した日程が「FOMC の年間日程として辻褄が合うか」を
検査し、**ひとつでも外れたら丸ごと捨てます**。

| 検査項目 | 落とす条件 |
|---|---|
| 会合数 | 年 6〜10 回の範囲外（通常は8回） |
| 曜日 | 火〜木以外（政策金利の発表は会合最終日で、実際にはこの範囲にしか来ない） |
| 年 | 見出しの年と違う日付が混ざっている |
| 間隔 | 前の会合から 25 日未満、または 75 日超 |
| 重複 | 同じ日付が2回出てくる |

検査に落ちたら何も取り込まず、従来どおり「手入力してください」というメールが飛びます。
**間違った金利発表日が静かに入るくらいなら、何も入らない方がまし**という考え方です。

さらに3つの安全弁があります。

- **手入力を絶対に上書きしない。** 埋めるのは手入力が尽きた**先の年**だけです。
- **出所が残る。** 自動取得ぶんの予定には「Fed の公式ページから自動取得したものです」と
  説明文に書かれます。
- **人間への引き継ぎ。** 新しい年を取り込んだら、`02_meetings.js` にそのまま貼れる形の
  メールが1度だけ届きます。貼っておけば以後は手入力が優先され、取得自体が行われません。

いま自動取得がどう動くかは、エディタで **`checkFomcAutoFetch`** を実行すれば確認できます。

```
取得先: https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm

✅ 2027 年  8 回
     2027-01-27  2027-03-17*  2027-04-28  2027-06-16*  ...

* 印は経済見通し(SEP)が同時公表される回。
現在の状態: 手入力 2026-12-09 まで / 自動取得 2027-12-15 まで
```

自動取得を使いたくない場合は `00_config.js` の `providers.fomcAutoFetch` を
`false` にしてください。手入力だけで動き、足りなくなればメールが届きます。

## データの確からしさ

カレンダーに入る予定は、ひとつずつ**日付の根拠**を持っています。説明文に必ず書かれ、
`dataQuality()` で全体の内訳を見られます。

| 根拠 | 意味 | 例 |
|---|---|---|
| **公式発表の日程** | 一次情報源が公表した日程そのもの | FRED の発表日、Fed 公式ページの会合日程、Nasdaq の決算日 |
| **集計サイトの日程** | 第三者の集計。実務上は正確だが一次ではない | Investing.com |
| **発表規則から算出** | 確定的な規則からの計算 | ISM＝第1営業日、失業保険＝毎週木曜、休場ルール |
| **概算（未確定）** | 概算、または人が書いたまま未照合 | CPI＝12日ごろ |

**概算のものは件名に `(予定日未確定)` と出ます。** 確かでないものを確かなように
見せない、というのがこの仕組みの目的です。

指定を書き忘れた予定は「概算」に倒れます。過大に名乗るより、控えめに倒れる方が安全です。

### FOMC の会合日程は自動で照合されます

手入力した日程（`02_meetings.js`）を、毎回 Fed の公式ページと突き合わせます。

- **一致** → 「公式で確認済み」に格上げ。何も言いません
- **食い違い** → **公式ページの方をカレンダーに入れ**、どこが違うかをメールで知らせます
- **取得できない** → 手入力のまま「未確定」扱い。確かだと言い張りません

人の記憶や写し間違いより、検査を通った公式ページの記載を信じる、という考え方です。

### 発表規則が当たっているかを測れます

`verifyRules()` を実行すると、過去12か月の実際の発表日（FRED）と、
「第1営業日」「12日ごろ」といった規則の予想を突き合わせて、指標ごとの
ずれと的中率を出します。規則は人が書いたものなので、測らないと信じてよいか
分かりません。

## 発表時刻はどこから来るか

**統計を出す機関そのものが公表している「発表予定表」から取ります。** 慣例値を
書き写したものではありません。

| 取得先 | 何が書いてあるか | どの指標 |
|---|---|---|
| [BLS 労働統計局](https://www.bls.gov/schedule/news_release/) | 発表日 **＋ 発表時刻** | CPI・PPI・雇用統計・JOLTS・雇用コスト指数・労働生産性 |
| [BEA 経済分析局](https://www.bea.gov/news/schedule) | 発表日 **＋ 発表時刻** | GDP・PCE（個人所得・支出）・貿易収支 |
| [Census センサス局](https://www.census.gov/economic-indicators/) | 発表日 **＋ 発表時刻** | 小売売上高・耐久財受注・住宅着工・新築住宅販売・建設支出 |

FRED は**発表日しか返しません**（時刻を持たない API です）。時刻が書いてあるのは
機関の予定表だけなので、そこが唯一の一次情報になります。

### 予定表に載っていない指標

ISM・ミシガン大・コンファレンスボード・地区連銀サーベイ・ADP・国債入札などは、
上の3機関の予定表には載りません。これらは `01_indicators.js` に書いた
**暫定値**に落ちます。その予定には必ずこう書かれます。

```
時刻の根拠 未確認の暫定値
…
自動同期: econ-calendar（発表時刻は未確認の暫定値）
```

**確かめていない時刻を、確かめた時刻のように見せません。** これがこの仕組みの
いちばん大事な約束です。

`providers.investing` を有効にすると、暫定値の上に集計サイトの実績時刻が
乗ります（`時刻の根拠 集計サイトの実績時刻`）。

### 時刻の出どころは3段階

| 表示 | 意味 |
|---|---|
| `発表機関の予定表` | BLS / BEA / センサス局の公表値そのもの。断り書きは付きません |
| `集計サイトの実績時刻` | Investing.com。一次情報ではないが実績値 |
| `未確認の暫定値` | カタログに書いた値。突き合わせていないので、そう明記します |

いま何件がどこから来ているかは `dataQuality()`、予定表がちゃんと読めているかは
`checkOfficialTimes()` で確認できます。

```
■ 発表時刻の出どころ
   発表機関の予定表 32 件 ■■■■■■■■■■■■■■■■
   集計サイトの実績   0 件
   未確認の暫定値    18 件 ■■■■■■■■■

   時刻を確かめられていないもの（予定に「未確認の暫定値」と出ます）
     米 ISM 製造業景況指数 × 2回
     米 ミシガン大 消費者態度指数 速報値 × 2回
   → checkOfficialTimes() で、予定表が読めているか確かめてください。
```

### 取得先を足す・直す

`00_config.js` の `officialSchedules` に URL を足すだけです。表の class や id には
一切頼らず、「1行の中に日付に読める欄・時刻に読める欄・名前らしい欄が並ぶ」という
形だけを見るので、たいていの機関の予定表はそのまま読めます。

```js
officialSchedules: [
  { name: 'BLS（労働統計局）',
    url: 'https://www.bls.gov/schedule/news_release/{{year}}_sched.htm',
    tz: 'America/New_York' },
  // ここに足す
],
```

足したら `checkOfficialTimes()` を実行すれば、読めたか・何件対応づいたかが
すぐ分かります。

> **抽出はゆるく、採用は厳しく。** 読み取れた行が極端に少ない、真夜中の時刻に
> なっている、表の年から離れすぎている——そういう行やページは丸ごと捨てて
> 暫定値に落とします。**間違った時刻が静かに入るくらいなら、暫定値だと
> 明記されている方がまし**という考え方です。

### 予想値・結果値も欲しい場合

`00_config.js` で **Investing.com を有効**にすると、予想値・前回値・結果値が
入ります。公式 API ではないため既定は無効です。サイト側の変更で動かなくなる
可能性がありますが、その場合も他の情報源だけで同期は続きます。

```yaml
providers:
  investing: true
```

> 説明文には、どのモジュールから来たかは**書きません**。情報源が一時的に落ちて
> 別の経路から同じ予定が組み立てられただけで説明文が変わると、中身は同じなのに
> 更新が走り続けるためです。書くのは「日付の根拠」と「時刻の根拠」の2つだけで、
> 利用者に意味があるのはそちらです。

### 時刻自体が不要なら

`display.allDay: true` にすると終日の予定になり、時刻を一切見なくなります。

## 設定

`00_config.js` の `CONFIG` を書き換えるだけです。

```js
filter: {
  minImpact: 55,        // このスコア以上だけ登録
  exclude: ['us_housing_starts'],   // 個別に外す
  include: ['us_trade_balance'],    // スコアに関係なく入れる
},

reminders: {
  S: [1440, 30],        // 最重要は前日と30分前に通知
  A: [30],
  B: [],                // 注目ランクは通知なし（カレンダーに載るだけ）
},

display: {
  allDay: false,        // true にすると時刻を持たない終日の予定になる
},
```

**しきい値の目安**（60日あたり・決算を除いた実測値）

| `minImpact` | 件数 | 内容 |
|---|---|---|
| 90 | 10 件 | CPI・雇用統計・PCE・FOMC だけ |
| 75 | 35 件 | ＋ PPI・ISM・小売売上高・失業保険・ミシガン大 |
| 55（既定） | 59 件 | ＋ 地区連銀サーベイ・住宅・国債入札・SQ・休場 |
| 0 | 74 件 | 全部 |

変更したら `preview` を実行して件数を確かめられます。

## データ源

3 層構造になっていて、**下に行くほど正確**、**上だけでも動く**のが設計方針です。

| 取得元 | キー | 何を提供するか |
|---|---|---|
| `rules` | 不要 | 発表日の**ルール計算**。「ISM 製造業＝第1営業日」「失業保険＝毎週木曜、祝日週は前倒し」など。通信ゼロで一通りのカレンダーができる |
| `fomc` | 不要 | FOMC 会合。手入力（`02_meetings.js`）＋公式ページからの自動取得。記者会見・議事要旨・ベージュブックは会合日から自動で導出 |
| `market` | 不要 | 休場・短縮取引・SQ・指数リバランス。取引所のルールから計算 |
| `official` | 不要 | **発表機関そのものの予定表**（BLS・BEA・センサス局）。発表日だけでなく **発表時刻** が書いてある唯一の一次情報。日付も時刻もここが最優先 |
| `fred` | 無料キー | **公式の発表日**。セントルイス連銀が各統計局の予定を公開しているので、`rules` の推定を確定値で上書きする。時刻は持たない |
| `earnings` | 不要 | Nasdaq の決算カレンダーから、設定した主要銘柄だけを抽出 |
| `investing` | 不要 | **予想値・前回値・結果値**。公式 API ではないので既定で無効 |

推定日には件名に `(予定日未確定)` が付き、説明文にも明記されます。
`FRED_API_KEY` を設定すると、FRED がカバーする指標は自動的に確定日に置き換わります。

<details>
<summary><b>予想値・結果値も欲しい場合（investing）</b></summary>

`00_config.js` で `providers.investing` を `true` にします。

Investing.com の公開エンドポイントを読みます。**公式 API ではない**ため、
サイト側の変更で動かなくなる可能性があります（その場合も他の取得元は生き続けます）。
利用は各サイトの利用規約を確認のうえ、自己責任でお願いします。

時刻がずれる場合は `CONFIG.investingTimezoneId` と `CONFIG.investingAssumeTz`
を足して調整してください。

</details>

## 開発

```bash
npm test          # 374 テスト・ネットワーク不要
npm run bundle    # src/*.js → dist/Code.gs
npm run coverage  # 一度も呼ばれていない関数を洗い出す
npm run mutate    # テストが本当にバグを捕まえるかを検査（下記）
npm run diff      # 日付の計算を、Python で独立に書いたものと突き合わせる
npm run check     # test + bundle
```

### テストの組み立て

テストは Apps Script と同じ「全ファイルをひとつのスコープに連結する」やり方で
ソースを読み込み、`Calendar` / `UrlFetchApp` / `MailApp` / `LockService` などを
差し替えて動かします。カレンダー API の偽物は**実 API と同じく `timeMin`/`timeMax` を
尊重する**ので、同期の冪等性（2回目は API を1回も叩かない）が本当に成り立つかまで
検証されます。FOMC 日程の自動取得も、公式ページを模した HTML を食わせて
「壊れた日程を確実に捨てるか」「手入力を上書きしないか」を確認しています。

`npm run coverage` は関数単位の実行カバレッジを出します（現在 187/187）。
呼ばれていない関数は、テストが通っていても何も保証されていません。

### 差分テスト（独立実装との突き合わせ）

実装とテストが同じ思い込みを共有していると、そのぶんは永久に見つかりません。
`npm run diff` は、**日付・タイムゾーン・祝日・発表規則の計算を Python で
独立に書き直したもの**（`tools/differential.py`）と、答えを1件ずつ突き合わせます。

```
66983 件を独立実装と突き合わせた

食い違いなし
```

突き合わせているもの:

| | 件数 | 相手 |
|---|---|---|
| 現地の壁時計 → 絶対時刻 | 58,800 | Python の `zoneinfo`（tzdata を直接読む。JS 側は ICU） |
| 絶対時刻 → 現地の日付 | 4,000 | 同上 |
| 連邦休日・市場の休場・短縮取引・復活祭 | 16年ぶん | 法律と NYSE の規則から書き直したもの |
| 発表規則の展開（19種類 × 9年） | 約 2,600 | 同上 |
| SHA-1 と base32hex | 507 | `hashlib` |
| 対象期間のラベル・営業日への寄せ | 1,044 | 同上 |

食い違ったら、**どちらが正しいかを一次資料で確かめてから**直します。実際に
このやり方で「元日が土曜の年、前年12月31日が営業日と数えられていた」という
ずれが見つかりました（連邦職員は休みなので、統計の発表もない）。逆に
「NYSE はその日を休場にしない」という方は JS が正しく、参照実装の方を
直しています。

### 性質テスト

`tests/props.js` は、**タイムゾーン・同期範囲・しきい値・表示設定・どの情報源が
生きているか・基準日**をでたらめに振り、どの組み合わせでも成り立つはずのことを
突きます（種は固定なので、失敗は必ず再現します）。

```
FUZZ_N=500 FUZZ_SEED=7 npm test   # 件数と種を変えて回す
```

見ているのは、たとえばこういうことです。

- 同じ入力でもう一度回したら、書き込みが1件も起きない
- 情報源が全部落ちても、予定も・実測の時刻も・発表された数値も消えない
- 同じ発表が2つ入らない、予定 ID がぶつからない
- 外部の情報源が生きていない回に「公式発表の日程」や「発表機関の予定表」を名乗らない
- 一次情報でない時刻には必ず出どころの断りが付き、暫定値は「未確認」と書かれる
- 基準日を1日ずつ進めても、書き換えは窓の端の数件で収まる

題材を人が並べるやり方だと、思いつかなかった組み合わせがそのまま抜けます。
実際、ここで「シドニー表示だと米 CPI が2日に分かれて2つ入る」「通信が不調な
日だけ決算がカレンダーから消える」という2件が見つかりました。

`npm run mutate` は**テストそのものを検査**します。修正を1つずつ巻き戻して、
対応するテストがちゃんと落ちるかを確かめる仕組みです（現在 69/69 検出）。
名前を渡すと一部だけ回せます（`npm run mutate -- 名寄せ`）。
落ちなければ、そのテストは何も守っていないということなので、テストの方を直します。

### 壊れにくさのために入れてあること

| | |
|---|---|
| 書き込みの再試行 | レート制限や一時的なエラーは待って試し直す（初回同期は 60〜130 件をまとめて書くので当たりやすい） |
| カレンダー消失からの復旧 | 覚えていたカレンダーが消されていたら、一度だけ探し直す |
| 多重実行の排他 | 手動実行と自動実行がぶつかっても二重に書き込まない |
| 設定の検証 | `CONFIG` を壊すと「どこがどうおかしいか」を言って止まる |
| 同期範囲の上限 | 設定を間違えても、何十年ぶんも展開して実行時間切れにならない |
| 情報源の隔離 | どれか1つが落ちても、残りで同期を続ける |
| **落ちた情報源の予定を消さない** | 「今回出てこなかった」を「もう無い」と解釈しない。つながらなかった情報源ぶんの予定はそのまま残す（しきい値を上げた等、人が外したものは消す） |
| **同じ発表を二重に入れない** | 情報源ごとに発表時刻の申告が少し違っても、指標の地元の日付で同じ発表だと見分ける |
| **他国の数値を混ぜない** | 取得した行の通貨から国を読み、違う国の指標には絶対に当てない |
| 書き間違いの検出 | 曜日の綴り誤り・不正な色 ID・カタログの書式崩れを、同期前に名指しで指摘する |
| 過去の記録の保護 | 同期範囲から外れた予定は、時間帯が重なっていても消さない |
| **出てこない指標の可視化** | 設定上どうやっても出せない指標を、`showStatus` が理由つきで挙げる |
| **壊れた応答で止まらない** | 取得先が途中で切れた・別物を返した・桁違いに大きい、のどれでも例外を漏らさず、読めた行だけを採る |
| **長すぎる中身を弾く** | 取得先のマークアップが変わって「値」の欄が長文を飲み込んでも、Google の上限を超える予定を投げない |

**重複しない仕組み**: 各予定の ID を `sha1(指標ID + 表示日)` から決めているので、
同じ指標の同じ日は必ず同じ ID になります。内容のハッシュも一緒に保存していて、
変化がなければ API を叩きません。ツールが作った予定には目印が付いているので、
手動で足した予定を消してしまうこともありません。

**なぜ CalendarApp ではなく Calendar API v3 か**: 予定 ID を自分で決められるのが
v3 だけだからです。`CalendarApp` だと ID を指定できず、上の仕組みが成立しません。

## 確かめていないこと・できないこと

正直に書いておきます。**カレンダーに正しいものが出ることがいちばん大事**なので、
どこまでが検証済みでどこからがそうでないかを、はっきりさせておきます。

### 1. 一部の指標は、発表時刻の一次資料がありません

BLS・BEA・センサス局の予定表に載る指標（CPI・雇用統計・GDP・PCE・小売売上高など）
は、発表時刻も機関の公表値そのものです。

一方、ISM・ミシガン大・コンファレンスボード・地区連銀サーベイ・ADP・国債入札は
これらの予定表に載らないため、`01_indicators.js` に書いた**暫定値**に落ちます。
この値は一次資料と1件ずつ突き合わせたものではありません。

ごまかさずに、その予定には `時刻の根拠 未確認の暫定値` と書かれます。
`providers.investing` を有効にすれば、そこに実績時刻が乗ります。
`dataQuality()` で何件が暫定値のままかを見られます。

`verifyRules()` が測れるのは発表「日」の規則の当たり具合だけで、時刻ではありません。

### 2. 影響度スコアと解説文は、データではなく判断です

「CPI は 98、住宅着工は 52」といったスコアと、「なぜナスダックに効くか」の
解説文は、統計的な計測ではなく作成者の判断です。しきい値の調整に使うぶんには
実用的ですが、**根拠のある数値ではありません**。

### 3. 通信する経路は、模擬応答でしか動かしていません

FRED・Nasdaq の決算カレンダー・Investing.com・Fed の公式ページとの通信は、
本物そっくりの応答を食わせたテストで検証してあります。ただし**開発環境から
実際にそれらのサイトへ接続してはいません**（接続できない環境で作っています）。

導入したら一度、エディタから次の3つを実行して、実際の応答で動くことを
確かめてください。

| 実行するもの | 見るところ |
|---|---|
| `runTests` | 日付計算・タイムゾーンが、その環境で正しく動くか |
| `checkOfficialTimes` | **BLS・BEA・センサス局の予定表を今の形のまま読めているか** |
| `checkFomcAutoFetch` | Fed の公式ページを今の形のまま読めているか |
| `dataQuality` | FRED が効いているか、時刻が何件一次情報から来ているか |

### 4. 日銀・ECB の会合日程は未登録です

`02_meetings.js` の `boj` と `ecb` は空のままなので、**この2つの指標は
カレンダーに出てきません**。会合日程は計算では出せず、確かめずに書くと
誤った金利発表日が入るので、空にしてあります。

必要なら公式ページを見て貼ってください（`showStatus` が URL ごと案内します）。

```js
boj: {
  verify_url: "https://www.boj.or.jp/mopo/mpmsche_minu/index.htm",
  meetings: [{ date: '2026-01-23', sep: false }, ...]
},
```

中国 PMI も発表規則を持たないので、`providers.investing` を有効にしたときだけ
出てきます。いまの設定で出せない指標は `showStatus` が理由つきで挙げます。

## 注意

- 発表日程・時刻・数値は各データ源に依存します。**投資判断は必ず一次情報で確認してください。**
- `removeAllEvents` は取り消せません。実行前に対象件数を確認してください。
- スクリプトのタイムゾーンと `CONFIG.timezone` は揃えてください（`runTests` が確認します）。
